# 03. Data Model

The database is the hardest thing to change later. This document fixes the conventions and the core tables for the **full** app. Phase 1 creates only the tables it needs, but they follow these designs exactly, so later phases add tables rather than restructure them.

## 1. Conventions

| Topic | Rule |
|---|---|
| Schemas | One Postgres schema per module: `identity`, `onboarding`, `content`, `coaching`, `ai`, `billing`, `bookings`, `community`, `gamification`, `events`, `notifications`, `admin`, plus `platform` for shared infrastructure (outbox, idempotency keys, job state) |
| Table names | `snake_case`, plural (`users`, `entitlement_grants`) |
| Primary keys | `id uuid` (UUIDv7, generated by the API) |
| Foreign keys | Always declared, always indexed. Cross-schema foreign keys allowed only to `identity.users(id)`. Other cross-module references store the ID without a foreign key and go through the owning module's interface |
| Timestamps | `created_at timestamptz not null default now()`, `updated_at timestamptz not null` (set by the repository) on every mutable table |
| Soft delete | `deleted_at timestamptz` on user-generated content (posts, comments, journal entries) and catalogue data. Hard delete for account erasure (F-106) via a job |
| Money | `amount_minor bigint` + `currency char(3)`. Never floats or numerics for money |
| Enums | Postgres `text` with a `CHECK` constraint, mirrored by a TypeScript enum in `packages/shared`. Adding a value is a migration. (Avoid native Postgres enums: they are awkward to change) |
| JSON | `jsonb` only for genuinely schemaless data (vendor webhook payloads, AI metadata). Never for data you will filter or join on |
| Time zones | Users and coaches store `time_zone text` (IANA, for example `Europe/London`). All stored times are UTC |
| Personal data | Columns holding sensitive personal data are listed in `admin.data_inventory` (a code file, not a table) with retention rules, used by deletion and export jobs |
| Ledgers | Append-only. No `UPDATE` or `DELETE` on ledger tables, enforced by a trigger |
| Text search | Postgres full-text search (`tsvector`) for content and community search until scale requires more |

## 3. Data retention defaults

| Data | Default retention | Notes |
|---|---|---|
| Chat and profile screenshots | Deleted 24 hours after analysis completes, unless the user saves the analysis with images | Open question to confirm |
| AI analysis results | Kept until the user deletes them or the account | |
| AI chat messages | Kept until user deletes the conversation or the account | |
| Journal entries | Until user deletes | Encrypted |
| Webhook payloads | 90 days, then payload nulled (row kept for idempotency) | |
| Logs | 30 days | No content in logs |
| Audit log | 7 years | Legal and financial |
| Financial records (purchases, payouts) | As required by tax law (typically 6 to 7 years), pseudonymised after account deletion | |
| Deleted account | Hard deleted after a 30-day grace period, except legally required financial records | |

## 4. Encryption

- Postgres and storage encrypted at rest by the host.
- Columns marked `_encrypted` use application-level envelope encryption (AES-256-GCM with a key from the environment, key ID stored alongside so keys can rotate). This protects the most sensitive content even from someone with database read access.
- Encryption helpers live in `platform/crypto`. Never hand-roll crypto elsewhere.
